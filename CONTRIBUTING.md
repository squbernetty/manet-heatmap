# Contributing

Thank you for contributing to this project.

## Ground rules

- All changes go through pull requests
- No direct pushes to the default branch
- Each pull request must reference an issue
- Authorship is tracked through commit history, pull requests, and issue discussion
- Major architectural changes require repository owner approval before implementation

## Workflow

1. Open or reference an issue before starting work
2. Create a feature branch for the change
3. Keep commits focused and readable
4. Open a pull request with a clear description of:
   - what changed
   - why it changed
   - any assumptions or limitations
5. Wait for review before merge

## Pull request expectations

Each pull request should include:

- linked issue
- summary of the technical change
- impact on modeling, performance, or data flow
- any test or validation performed
- known gaps or risks

## Credit and ownership

Contributions are credited through Git history, pull requests, issue ownership, and documented design discussion.

Submitting a contribution does not transfer repository ownership.
